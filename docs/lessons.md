# Lessons — mistakes turned into rules

Append-only. Each entry is a **finding-class we actually hit** (or a near-miss caught in
adversarial review), rewritten as a **one-line preventive rule** so it never recurs.
Newest at the bottom. Consult this list before building; add to it every time review or CI
catches a class of mistake not already here.

Format: `- **<short name>** — <one preventive rule>. (<where it bit us>)`

## Rules

- **Enforced-flag honesty** — never ship a settable toggle the feature ignores; a stored 'off' the code doesn't read is a false promise, so gate unwired keys read-only (`enforced=false`) until their consumer lands. (ADR-0013)
- **Audit must commit, so return don't raise** — when an audit event must persist in the request transaction, return the denial response; a raised `HTTPException` propagates through the transaction dependency and rolls the audit write back. (ADR-0017)
- **No check-then-write (TOCTOU)** — never guard a write with a prior read under concurrency; enforce uniqueness/single-use in storage (partial unique index, `DELETE ... RETURNING`, `FOR SHARE`), so the DB serializes the race. (ADR-0012 duplicate connections, ADR-0013 authority race, ADR-0017 pending-auth)
- **Revocation enforced centrally, everywhere** — a revoked grant must be refused at authentication AND on the refresh/pull path, and its secret material deleted on revoke and re-link — not just blocked at one gate. (ADR-0017 token vault; ADR-0013 revocation flips authority)
- **PHI can leak below the app** — app logs being clean is not enough; keep request/structured logs and the proxy/log layer PHI-free by construction, and audit PHI reads/writes with counts/references only, never values. (CLAUDE.md §5; ADR-0012/0014/0018)
- **Migrations that change types need care** — `ALTER TYPE ... ADD VALUE` and NOT-NULL/enum additions run in an autocommit block with backfill; downgrades are reversible OR they explicitly refuse rather than orphan/data-lose. (ADR-0014 enum, ADR-0012 downgrade-refuses)
- **Secret-scanner false positives** — never write `password = "..."` literals even in tests; use uppercase `SYNTHETIC_` constants so the secret scanner stays meaningful. (secret-scan gate; CLAUDE.md §5)
- **No wall-clock in tests** — inject a fixed `now` into anything time-dependent (expiry, rate windows); time-of-day-dependent assertions flake in CI. (ADR-0013, ADR-0017 limiter)
- **Never silently truncate parsed input** — a value from untrusted parsed text must fully consume its token or be skipped with a warning; a prefix match turning "1,234.5" into 1.0 is a corrupted measurement that looks valid. (ADR-0014 numeric truncation)
- **Never compute cross-unit deltas** — if two readings carry different unit strings, show "unit changed / not judged"; do not compute a delta or a better/worse verdict across units. (ADR-0015/0016 unit-change honesty)
- **Bound untrusted uploads before materializing** — cap Content-Length before the body is spooled, cap decompressed output, and run sync parsing off the event loop; a byte cap that fires after `read()` has already buffered the whole body is no cap. (ADR-0014 hardening)
- **Fail closed, never fail plaintext / never fail open** — an unconfigured secret key falls back to the in-memory vault (never plaintext to disk); an unset ops gate returns 403; a malformed key stops boot and never echoes the rejected value. (ADR-0017)
- **UI is proven in a real browser, not by mocks** — a passing unit/msw test does not prove a UI portion works; drive the built app in Chromium/Playwright and confirm render + key flows + zero new console errors before Done. (Definition of Done)
- **Reimbursement guidance is not billing advice** — never assert a CPT/HCPCS code, threshold, or rate from memory; source every figure, mark it PENDING coder/compliance validation, and capture billable *facts* generically instead of hard-coding payer code numbers. (docs/product/reimbursement-analysis.md)
- **Observability is a PHI-leak surface — exclude by construction** — metric labels and error events must carry route *templates* + fixed vocabularies (method/status/type) only, never a raw path, exception message, query/body/header, or any value; derive auth-denial/rate-limit signals from the status label instead of a per-subject counter, and build error events from a fixed whitelist so `str(exc)` can never reach them. (ADR-0021 metrics + error seam)
- **A new dep's license string is spelled the way the tree spells it** — a permissive dep can still fail the blocking license scan on an unlisted SPDX combo (e.g. `Apache-2.0 AND BSD-2-Clause`); add the exact reported string to the CI allowlist when introducing the dependency, not after CI goes red. (ADR-0021 prometheus_client)
- **A new outbound/egress seam ships OFF and config-gated** — error reporting, AI narration, and any PHI-adjacent egress default to disabled, activate only on an explicit operator/BAA action, POST a scrubbed payload to a self-hostable/BAA-covered destination, and fail-safe (a reporter error never breaks the request). Mirror the Narrator seam; never hardcode a SaaS DSN. (ADR-0021 error reporter; ADR-0011 narrator)
- **Per-process metrics lie under multiple workers** — a module-level `CollectorRegistry` exposes only the one worker a scrape hit, so round-robin makes counters look like they reset; run `prometheus_client` multiprocess mode (shared `PROMETHEUS_MULTIPROC_DIR`, `MultiProcessCollector` scrape, gauge `multiprocess_mode`), wipe the dir on fresh start, and clear dead workers via a real worker-exit hook (gunicorn `child_exit` → `mark_process_dead`) — bare `uvicorn --workers` has no such hook. (ADR-0021 multi-worker /metrics)
- **A 500 must still log and correlate** — resolve the request id in the outermost middleware BEFORE calling downstream and stash it on `request.state`, and log one line for every request including unhandled exceptions (status 500, route template or `__unmatched__`, then re-raise), so the error-seam event and the log line share one id even when the client sent no `X-Request-ID`. (ADR-0021 error-seam correlation)
- **No credentials in argv** — never pass a password-bearing DSN to `pg_dump`/`psql`/`pg_restore` (or a parser) on the command line; `/proc/<pid>/cmdline` is world-readable, so hand libpq the password only via a 0600 `.pgpass`/`PGPASSFILE` (+ `PGHOST/PGPORT/PGUSER`) and put only plain database names in `--dbname`. (ADR-0021 pg_backup_drill.sh)
- **Browser E2E hits the BUILT app, and its console gate must know network noise from app faults** — drive `vite build`/`vite preview` (never the dev server) in the pinned Chromium; intercept only `fetch`/`xhr` so shared client-route/API prefixes (`/clinic*`) still serve `index.html`; and scope the zero-console-errors gate to `pageerror` + non-network `console.error`, because Chromium logs a "Failed to load resource: … N" line for EVERY handled 4xx/5xx (the ADR-0015 refresh-on-401 restore, ADR-0013 409 rollbacks, ADR-0012 neutral 404) — allowlist that network line ONLY for the exact designed status codes (401/404/409/422), never a bare `\d+`, or a real 500 (including an unmocked-path 500) slips through; and ship a self-check spec that proves the gate both fails on a real thrown error and does not false-positive on the allowed statuses, so a weakened gate is itself caught. (ADR-0022 E2E harness)
- **A success-status mock must return the FULL schema shape, not just the overridden field** — an early `return status,body` branch that fires for any set status will emit a partial 2xx body (e.g. `{superseded:true}` missing the required `check_in_date`/`daily_score`) — a fiction the real Pydantic response could never produce. Merge scenario overrides onto the full default body for 2xx and only return raw bodies for 4xx/5xx errors. (ADR-0022 ADL mock)
- **Two test runners, one glob collision** — Vitest's default `*.spec.ts` glob will swallow Playwright specs (which import `@playwright/test`) and crash the unit run; scope Vitest to `src/**` (or move E2E to a distinct extension) so the browser suite and the jsdom suite never cross. (ADR-0022 vitest/playwright split)
- **A generated native project is not TypeScript source — fence it off from the JS toolchain** — `npx cap add android` drops a whole `android/` tree (Java/Gradle/XML) plus a COPIED minified web bundle under `assets/public`; ESLint `.` and Prettier `.` will walk it and drown in thousands of errors on the minified bundle. Add `android` to both the ESLint `ignores` and `.prettierignore` the same commit you add the platform. Vitest (`src/**`) and Playwright (`e2e/**`) are already scoped so they don't pick it up. (ADR-0023 Capacitor scaffolding)
- **Harden the keystore .gitignore the moment the native project lands** — Capacitor's generated `android/.gitignore` leaves the `*.jks`/`*.keystore` lines COMMENTED OUT. A signing key is a production secret; uncomment and extend them (`*.keystore`, `keystore.properties`, `signing.properties`) before the first commit so a release key can never be accidentally tracked. (ADR-0023)
- **A native wrapper's audit noise is in devDeps; gate on the production tree** — adding `@capacitor/cli`/`@capacitor/android` (dev) lights up `npm audit` with high/critical findings, but the blocking CI gate is `npm audit --omit=dev` + the production license allowlist. Confirm the PROD tree stays clean (`@capacitor/core` is MIT) rather than reacting to the dev-tree count. (ADR-0023)
- **When the env can't fully build the artifact, name the boundary and move the real proof to CI** — no Android SDK locally means no APK/emulator; don't claim device-verified. Verify what's verifiable (web target unregressed, `cap sync` works, gates green) and wire the compile proof (`gradlew assembleDebug`, debug-signed, no keystore) into a dedicated CI `mobile` job, leaving on-device smoke to the user's `cap run android`. (ADR-0023)
- **Pin a Capacitor plugin to the Capacitor-major it targets — `cap sync` tells you, peerDeps don't** — the @aparajita plugins don't declare `@capacitor/core` as a peer dep, so `npm view … peerDependencies` is empty; the real signal is the plugin's `devDependencies["@capacitor/cli"]` major AND the `cap sync` warning ("doesn't officially support Capacitor ^6 yet"). For Cap 6: secure-storage `^6`, biometric `~9.0` (their `7.x`/`9.1+` lines jumped to Cap 7). A too-new plugin syncs with a warning and can break `assembleDebug`. (ADR-0024)
- **Make platform/native seams injectable or locally-mockable — don't fight `vi.mock` on an inlined native ESM dep** — mocking `@capacitor/*` or a plugin across the whole app import graph is fragile (inlining a dep to fix its extensionless ESM actually blocks `vi.mock` from intercepting it). Centralize `isNativePlatform()` in one local module, inject the secure-store accessor into the backend, and factor the native decision into a plain async function — then unit-test those via reliable local mocks/injection. Globally stub the plugins in the test setup so web suites load; leave true native calls to on-device. (ADR-0024)
- **A synchronous read the first render depends on cannot become async without a flash** — the auth restore-vs-anonymous decision is read synchronously in a `useState` initializer. Native secure storage is async, so keep a synchronous `peek` (web: live `sessionStorage`; native: an in-memory mirror primed by an awaited `load`) and start native in `restoring` until the mirror is primed — never change the web timing. (ADR-0024)
- **A biometric/security gate fails CLOSED on an error, OPEN only on a known-safe state** — distinguish "no biometry enrolled" (the plugin RESOLVES `{isAvailable:false}` → safe to allow, don't lock the user out) from "the gate threw" (bridge error/spoof → deny the silent restore, fall back to password). Catch-all `→ allow` silently degrades the second factor. And make the durable logout-delete retry (a fire-and-forget single `remove()` that rejects leaves a still-valid token to resurrect the session next launch). (ADR-0024 review)
- **Adding test files can expose a latent parallel-worker flake — serialize files, don't just bump timeouts** — a component test that was reliable can start failing ~1-in-4 once enough new test files raise cross-file CPU/scheduler contention; the signature is a FAST `findBy*` detach/timing race, not a slow-render timeout, so `asyncUtilTimeout` does not help. `fileParallelism: false` (run files one at a time; tests within a file still run) makes the jsdom suite deterministic for a few extra seconds. Prove the fix by running the full suite many times, not once. (ADR-0024 review)
- **Don't build native plumbing for a flow that doesn't exist yet — check the frontend first** — the roadmap coupled "native shell" with "SMART OAuth-callback handling," but the frontend had no EMR-connect UI (`grep '/emr'` empty) and sandbox registration is a later wave. Building the app-scheme/deep-link handler now would be untestable dead code. Ship the concrete half (shell), defer the coupled half to where its UI + sandbox land, and record the deferral. (ADR-0025)
- **Official Capacitor plugins import cleanly in jsdom; some community ones don't** — the official `@capacitor/status-bar|splash-screen|app` load fine under vitest (proper ESM), unlike the `@aparajita/*` plugins that needed a setup stub. Verify with a one-line import test before assuming. Keep every native call gated behind `isNativePlatform()` so the web/E2E path never invokes them, and unit-test the pure decision (`backAction`), not the plugin wiring. (ADR-0025)
- **A per-connection OAuth parameter must be resolvable on BOTH handshake hops from persisted state** — the client_id chosen when building the authorize URL must be re-derived identically at the token exchange (a vendor id on hop 1 + the fallback on hop 2 fails every exchange); resolve it from what the connection record persists (`provider_name`) and load the record BEFORE the token exchange, so no schema change or pending-state field is needed. (ADR-0028 per-provider client ids)
- **Don't trust `context.setOffline` alone to fail an INTERCEPTED request** — Playwright route interception sits in front of the network emulation, so a `page.route`-fulfilled API call can still succeed "offline"; sever the specific route explicitly (`route.abort('internetdisconnected')`) to produce the real fetch TypeError, keep `setOffline` for what it reliably does (`navigator.onLine` + firing the real 'online' event on restore), and allowlist ONLY that exact net-error line (`net::ERR_INTERNET_DISCONNECTED`) in the console gate — never a broad net::ERR pattern. (ADR-0030 offline E2E)
