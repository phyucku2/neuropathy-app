1 · The product in one paragraph

A privacy-by-design digital health platform that fuses three independent data streams — patient-reported daily function (walking, stairs, balance-confidence check-ins), lab results pulled from the patient's own EMR (SMART on FHIR), and objective balance/gait measurements from BioMech reports — into one explainable trajectory of how a person's neuropathy is trending (improving / stable / declining, with the named signals and confidence behind it). Patients own their data and the sharing switch; clinicians get a consent-gated panel. Deliberately non-diagnostic. Runs as a web app and a native Android app from a single codebase.

2 · Patient app — features

  • Accounts & sign-in — email registration/login, Argon2id password hashing, JWT access/refresh sessions; access token memory-only; session restore on reload.
  • Home trajectory view — the explainable hero: direction, confidence, the specific signals driving it, and honest "not enough data" states; plain-language AI narrative available behind a business-associate gate (off by default).
  • Daily check-in (ADL) — 0–4 ratings for walking, stairs, balance confidence; keyboard-accessible; same-day re-submission supersedes cleanly with a visible notice.
  • Trends — per-metric line charts with axis/unit summaries, better/worse judgments (direction-of-better aware), unit-change and insufficient-data guards.
  • Add data — BioMech balance/gait PDF upload parsed into research-grade observations, with parser warnings surfaced as plain text; size caps enforced before the body is read.
  • EMR connection — SMART on FHIR OAuth/PKCE patient-authorized lab import (backend complete since V1; the patient-facing connect UI is the portion building right now).
  • Sources (consent center) — server-enforced feature toggles the patient controls: data ingestion, EMR connect, AI narrative, share-with-clinic; optimistic UI with verbatim server messages on conflicts; clinic-managed toggles clearly labeled — but share-with-clinic always stays patient-held, even when a clinic manages other toggles.
  • Clinic connections — approve/decline clinic invitations; disconnect with two-tap confirm; data flow stops immediately.
  • Account & data deletion — password-confirmed, rate-limited, transactional destruction of every patient-owned record including EMR token vault entries; PHI-free audit trail retained anonymously; never blockable by any toggle. (The hard Google Play requirement — shipped.)

3 · Clinician app — features

  • Consent-gated panel — only patients who granted access appear; invitations are rate-limited and non-enumerating (you can't probe who has an account).
  • Patient detail — shared trajectory with prominent non-diagnostic framing; cross-source trend table (BioMech + labs + ADL in one view, "not judged" where data is thin); paginated raw observations.
  • Features tab (capability orders) — clinicians can manage clinic-managed toggles with expiry dates ("orders" pattern, renewals as explicit re-enables); patient-held consent renders read-only — proven in a real browser by the E2E suite.
  • Privacy screens — neutral "Patient not found" for anything not consented (404-over-403: no existence leaks).

4 · Mobile (Android) — shipped

  • Native app via Capacitor — the same verified SPA in a native shell; package id com.ahwg.neuropathy (publisher-confirmed, permanent at first Play upload); CI builds an installable APK on every PR.
  • Security posture beyond web — refresh token in the Android Keystore (encrypted at rest), biometric/device-credential unlock before a persisted session is revealed (fails closed on gate errors), allowBackup=false (no PHI in device backups), TLS-only.
  • Native shell — branded status bar/splash, safe-area handling, hardware back button; splash-hang guarded.
  • Play release machinery — upload-key signing (Play App Signing), one-click signed-AAB workflow, real icon/splash/feature graphic/5 store screenshots (script-generated), Data-Safety form pre-drafted from the actual data flows, privacy-policy scaffold, full release runbook.
  • iOS — deliberately deferred until the owner's Apple DUNS/ID switch; the Capacitor architecture makes it an add-platform step, not a rebuild.

5 · Platform & backend — features

  • API — async FastAPI; standards-based intake (FHIR R4 / LOINC labs with reference ranges); explainable deterministic trajectory engine; BioMech PDF ingestion; capability enforcement server-side on every write path.
  • Data layer — PostgreSQL with SQLAlchemy 2.0 async, Alembic migrations (6, files-only discipline), request-scoped transactions; a full in-memory twin of every store so the app runs without a database for demos/tests (parity pinned by tests).
  • Security — per-operator ops identities (no shared bootstrap tokens in steady state), encrypted EMR-token vault with delete-on-revoke, invitation rate limiting, deletion-attempt rate limiting, PHI-free audit log on reads and writes, secret scanning + dependency audits + license allowlists blocking in CI.
  • AI narrative layer — validated, off the request path, BAA-gated and off by default; PHI never leaves without the gate; disclosure audited.
  • Observability & ops — PHI-free Prometheus metrics, request-ID-correlated structured logging, optional PHI-scrubbing error reporting seam, health/readiness endpoints, tested Postgres backup drill, deploy + restore runbooks, staging docker-compose, hardened multi-stage container images (built in CI).
  • Compliance pack — HIPAA ops checklist, BAA inventory, incident-response runbook — with honest "covered-entity's responsibility" boundaries.

6 · Engineering quality system

  • Every portion ships through: implementation → two independent adversarial reviews (security/privacy + correctness) → per-finding fixes with regression tests → full gates → merge. 26 ADRs record every decision; a lessons log turns each mistake into a preventive rule.
  • Gates (all blocking in CI): backend ruff + mypy-strict + pytest with 100% coverage including live-Postgres integration tests; frontend strict TS + zero-warning ESLint + Prettier + 157 unit tests (≥90% coverage) + production build; 31 real-browser Playwright specs against the built bundle with a self-checked zero-console-error gate; Android APK compile job; security/license scans; Docker builds.
