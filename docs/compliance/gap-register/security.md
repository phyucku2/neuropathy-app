# Security Gap Register (OWASP ASVS / OWASP Top 10 / MASVS)

> **This is an engineering gap register and remediation plan — NOT a penetration-test report, security certification, or claim that the system is secure in production.** No production environment exists; all findings are against source code. See [README](./README.md) for the honest product status and legend.

## Summary

The application-layer security posture is unusually strong and largely met-in-code: Argon2id hashing, kind-enforced JWTs with central revocation, consent-scoped 404-over-403 multi-tenant isolation, ORM-only (parameterized) data access, a fail-closed Fernet secret vault, disciplined PHI-free logging/metrics/error-reporting, PKCE SMART-on-FHIR with least-privilege scopes, hardened PDF ingest, and blocking CI dependency/license/secret gates. The most concrete engineering gap is that the primary auth surface — `POST /auth/login` and `/auth/refresh` — has no rate limiting or lockout at either app or edge layer; other gaps are a missing token-revocation list, no breached-password screening, no SAST in CI, and audit-log tamper-evidence resting on discipline rather than cryptography. This is a gap register, not an attestation: the product handles **synthetic data only**, has no deployed production environment, and the hard pre-PHI blockers (TLS in transit, full-disk/DB encryption at rest, edge WAF/rate-limiting, signed BAAs) are unconfigured organizational/ops actions outside this codebase.

Adversarial review downgraded the password-hashing row from met-in-code to **partial** (the requirement demands a *reviewed cost profile*; the code uses library-default Argon2 parameters), re-owned CORS to **both** (the control is "met by absence" and rests on the same-origin deployment topology), and added five previously-omitted requirement families (MFA, password-reset, registration anti-automation, PHI-read-access audit completeness, contingency/backup) as rows below.

## What this lens does NOT assert

- It does **not** assert the system is secure in production or has passed a penetration test; there is no deployed environment and no third-party assessment.
- "met-in-code" means the control is demonstrable at the cited source path; it does not assert the control is configured, deployed, or operating.
- The hard pre-PHI blockers (TLS in transit, full-disk/DB encryption, edge WAF/rate-limiting, signed BAAs) are organizational/ops actions outside this codebase and are not complete.
